# Codex 호환 연결 기록

Ticket: 20260913_2312-agent_harness-Codex_호환_연결

기존 Claude 절차를 변경하지 않고 Codex가 같은 원본을 읽도록 연결 파일을 추가했다.
사용자가 요청한 Codex 호환 확인·필요 파일 추가·push를 이번 적용 범위의 근거로 사용했다.
별도 과정 개선 의견은 작업 공간 루트 `AGENT_HARNESS_FEEDBACK.md`에만 기록한다.

## 문제와 적용안

기존에는 Codex 기본 탐색 파일 `AGENTS.md`가 없었다.
추가한 `AGENTS.md`가 `CODEX.md`를 읽도록 지시하고, `CODEX.md`가 기존 `CLAUDE.md`와 `.claude/commands` 원본을 연결한다.
`.codex/README.md`는 구성 안내이며 실행 설정을 변경하지 않는다.
루트 `README.md`에 Codex 사용 경로를 추가했다.

공통 지침 전체 복제는 두 원본의 내용이 어긋날 수 있어 선택하지 않았다.
임의 이름인 `Clodex.md`를 자동 인식 파일로 안내하지 않고 표준 진입점과 명시적으로 읽는 `CODEX.md`를 사용했다.

## 예외와 위험 검토

- Claude hook은 Codex에서 이 연결만으로 실행되지 않으므로 활성 문서 직접 확인을 명시했다.
- 기존 코드 마커 문자열은 유지하고 Claude 공동 작성자 표기만 Codex 단독 작업에 적용하지 않도록 했다.
- Harness 문서 경로와 소비 프로젝트 산출물 경로를 구분했다.
- 소비 프로젝트 루트 세션에서는 서브모듈의 진입점이 자동 발견되지 않으므로 루트 연결 예시를 제공했다.
- 기존 승인 절차, 코드 마커 체계, hook 파일 및 과정 개선 제안은 수정하지 않았다.

## 검증과 전파 범위

Markdown 참조 대상 존재와 필수 마지막 섹션 순서, Git diff 공백 오류를 확인한다.
코드 변경이 없는 문서 연결이므로 빌드와 단위 테스트 대상은 없다.
새 Codex 세션에서 실제 지침 로딩을 확인하는 절차를 `CODEX.md`에 제공하며, 이번 세션의 정적 검토와 새 세션 실증은 구분한다.
push 대상은 사용자가 지정한 Harness 원본 저장소의 main이다.
소비 저장소들의 루트 지침과 서브모듈 포인터 갱신은 이번 원본 저장소 연결 추가에 포함하지 않는다.
따라서 기존 소비 저장소가 이미 Codex 호환 상태라고 주장하지 않는다.

## 요약

- Codex 표준 진입점과 기존 Claude 지침을 연결한다.
- 기존 과정 개선은 별도 피드백으로 남긴다.
- 소비 저장소 도입 방법과 실제 세션 확인 절차를 문서화한다.

## 사용자 결정 사항

1. Codex 호환 파일이 필요하면 추가하고 push한다.
2. 과정 개선 의견은 작업 공간 루트에만 기록하고 즉시 적용하지 않는다.
